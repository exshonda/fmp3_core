# RISC-Vコア依存部の位置づけ

RISC-Vコア依存部は，カーネルのターゲット依存部の中で，RV32I/RV64I/RV32Eに準拠したプロセッサコアを持つターゲットシステム（チップ）に共通に使用できる部分である．

ただし，これに該当するすべてのRISC-Vコアに対応できているわけではない．新しいチップにポーティングする際には，コア依存部に何らかの修正が必要になることも多いと思われる．

RISC-Vコアのプロセッサコア略称を"riscv"とする．GNU開発環境向けのRISC-Vコア依存部を置くディレクトリはarch/riscv_gcc/commonとなる．

RISC-Vの場合，一部の割込みのためのローカルの割込みコントローラ（CLIC）が定義されているがチップによっては無効となっている場合ある．そのため，ローカル割込みに関する記述はRISC-Vコア依存部に含めるが無効することを可能とする．

多くの外部割込みは外部割込みコントローラを経由して接続する．外部割込みコントローラは，任意のものを接続することが可能である．外部割込みコントローラに依存部依存する部分はRISC-Vコア依存部に含めないことを原則とするが，多くのチップに採用されている割込みコントローラであるPLIC（Platform-Level Interrupt Controller）に依存する部分（PLIC依存部）は，RISC-Vコア依存部のディレクトリに置いている．

今後，その他の標準化された外部割込みコントローラについては，RISC-Vコア依存部のディレクトリに置く可能性がある．

# 必須となる拡張

RISC-Vコア依存部では，Base Integer Instruction Setに加えて以下の拡張を必須とする．

- “Zicsr”, Control and Status Register (CSR) Instructions
	- CSR へのアクセスに使用する．
- “A” Standard Extension for Atomic Instructions
	- コア間の排他制御に使用

# 各拡張への対応

## RV32とRV64のコード共有

### __riscv_xlen マクロによる切り替え
- RV32とRV64でコードを切り分ける必要がある場合は，RISC-V C API Specification で定義された __riscv_xlen マクロで切り替える．
- RV32の場合は'32'に，RV64の場合は'64'に定義される．

### アセンブラマクロ
アセンブラに切り替えのifdefを減らすために，次のマクロの定義を切り替える．
- XREG_SIZE : 汎用レジスタのバイトサイズ
- INTPTR_T_SHIFT : intprt_t型のテーブルにアクセスする際のシフト数
- lx : 汎用レジスタのロード命令
- sx : 汎用レジスタのストア命令
- lwu : 32bitロードの0拡張

### Machine Timer のレジスタのアクセス

RV32では4byte単位，RV64では8byte単位でアクセスするよう切り替える．

### サイクルカウンタのアクセス

RV32では4byte単位，RV64では8byte単位でアクセスするよう切り替える．

### intprt_t 型変数のアライメントサイス

RV32では4byte単位，RV64では8byte単位でアクセスするよう切り替える．

### xlog_sysの出力フォーマと

RV32では "0x%08x" で，RV64では，"0x%016lx"で汎用レジスタの値を出力する．

## RV32E対応
- RV32E対応でコードを切り分ける必要がある場合は，RISC-V C API Specification で定義された __riscv_32e マクロで切り替える．	
- RV32Eの場合は'1'に定義される
- 現状の切り替え内容は次の通りである
	- CPU例外の情報を記憶しているメモリ領域の構造
		- t3- t6(x28-31),a6(x16),a7(x17) を含まない	
	- スタックサイズのアライン単位（CHECK_STKSZ_ALIGN）
		- RV32Eは4byteそれ以外は16byte
	- ディスパッチャや割込み・例外ハンドラ出入口処理
		- x16-x31 を保存復帰対象としない

### ディスパッチャや割込み・例外ハンドラ出入口処理でレジスタの保存・復帰数を定義するマクロ
- TNUM_RISCV_DISP_XREG
	- ディスパッチ時に保存する汎用レジスタ数
- TNUM_RISCV_INT_XREG
	- 割込み・例外ハンドラ入口処理で保存する汎用レジスタ数
- TNUM_RISCV_INT_DISP_XREG
	- 割込み・例外ハンドラからのディスパッチで保存する汎用レジスタ数

## F/D拡張対応
- F拡張及びD拡張対応でコードを切り分ける必要がある場合は，RISC-V C API Specification で定義された __riscv_flen マクロで切り替える．
- F拡張の場合は'32'に，D拡張の場合は'64'に定義される．

### アセンブラマクロ
- アセンブラに切り替えのifdefを減らすために，次のマクロの定義を切り替える．
	- FREG_SIZE : 浮動小数点数用汎用レジスタのバイトサイズ
	- lf : 浮動小数点数用汎用レジスタのロード命令
	- sf : 浮動小数点数用汎用レジスタのストア命令

###  CPU例外の情報を記憶しているメモリ領域の構造
- 浮動小数点数用汎用レジスタの型を FREG_T に定義する
- F/D拡張をサポートする際にはレジスタを追加

### ディスパッチャや割込み・例外ハンドラ出入口処理
- F/D拡張をサポートする際には浮動小数点数用汎用レジスタを保存復帰の対象とする．

### ディスパッチャや割込み・例外ハンドラ出入口処理でレジスタの保存・復帰数を定義するマクロ
- TNUM_RISCV_DISP_FREG
	- ディスパッチ時に保存する浮動小数点汎用レジスタ数
- TNUM_RISCV_INT_FREG
	- 割込み・例外ハンドラ入口処理で保存する浮動小数点汎用レジスタ数
- TNUM_RISCV_INT_DISP_FREG
	- 割込み・例外ハンドラからのディスパッチで保存する浮動小数点汎用レジスタ数

# システム状態の管理

## プロセッサモード

FMP3カーネルのRISC-Vコア依存部では，アプリケーションプログラムとカーネルの大部分を，マシンモードで実行する．

スーパーバイザーモードで動作させる方法もあるが，RTOSを動作させるレベルのチップではスーパーバイザーモードを持たない場合があることから，マシンモードでの実行とする．

RISC-Vでは現在の動作モードを取得する機能がないことから，FMP3カーネルのスタートアップコードを呼び出す時点でマシンモードとなっている必要がある．

## カーネル管理外の割込み

RISC-Vコア依存部の標準では，カーネル管理外の割込みは設定しない．ただし，ターゲット依存でカーネル管理外割込みを設定したい場合は，TOPPERS_SUPPORT_NONKERNELINT をマクロ定義することにより，CPUロック状態への遷移や解除関数を無効し，ターゲット依存部で設定することが可能である．

## 全割込みロック状態の管理

全割込みロック状態では，マシン割込みをマスクする．具体的にはmstatus.MIEをクリアする．

## コンテキストの管理

実行中のコンテキストをプロセッサモードで判断することができないため，例外（割込みハンドラおよびCPU例外ハンドラ）のネスト段数を変数（これを，例外ネストカウント(exncnt)と呼ぶ）で管理し，例外ネストカウントが0の時にタスクコンテキスト，0より大きい場合に非タスクコンテキストであると判断する．

## CPUロック状態の管理

標準では，CPUロック状態では，マシン割込みをマスクする．具体的にはmstatus.MIEをクリアする．
全割込みロック状態とCPUロック状態を区別できる必要はないことから，mstatus.MIEビットが立っていれば，CPUロック状態であると判断す
る．

## 割込み優先度マスクの管理

割込み優先度マスクの管理は，割込みコントローラによって行う．そのため，RISC-V依存部には含めない．

PLICの場合には，priority threshold レジスタにより，割込み優先度マスクを管理する．

## 割込み要求禁止フラグの管理

割込み要求禁止フラグの管理は，割込みコントローラによって行う．そのため，RISC-V依存部には含めない．

PLICの場合には，割込みを割り付けた Hart n M-mode enables レジスタにより，セット/クリアする．

## 割込みに関するその他の操作

割込みに関するその他の操作は，割込みコントローラによって実現する．そのため，RISC-V依存部には含めない．

PLICの場合には，割込み要求のプローブは，Interrupt Pending Register によって実現する．割込み要求のクリアはサポートしない．


# ロック変数のキャッシュラインの専有

## 背景：なぜ専有させる必要があるか

FMP3のロック（ジャイアントロック，カーネルオブジェクトのスピンロック，SILスピンロック）は，
RISC-V依存部では **LR/SC**（`lr.w.aq`／`sc.w.rl`．`riscv_insn.h` の `riscv_tas_uint32`，
`core_sil.h` の `TOPPERS_test_and_assign`）で実現している．

LR/SCの**予約セットの大きさはISA上「実装依存」**であり，実装ではキャッシュライン粒度と
するのが一般的である．**予約セット内のいずれかのアドレスへのストアで予約は失効する**ため，
複数のロックや無関係な変数が同一キャッシュラインに同居していると，

- あるハートのロックAの解放（`sc.w`）が，別のハートのロックBに対する予約を失効させる
- 無関係な変数（ログカウンタ等）への**通常のストア**でも予約が失効する

という形で，SCの失敗が繰り返される．ISAの前進保証（constrained LR/SC sequence）は
「他のハートが予約セットにストアしないこと」を条件とするため，この状態は保証の枠外である．
詳細は `riscv_memo.md`「“A” Standard Extension」を参照．

ARM依存部（LDREX/STREX）でも排他予約グラニュールに関して同じ問題があり，同様の対処をしている．

## 対処：LOCK型をキャッシュライン長の配列とする

`core_kernel_impl.h` で，LOCK型をキャッシュライン長の配列として定義する．

	#ifndef RISCV_CACHELINE_SIZE
	#define RISCV_CACHELINE_SIZE  64
	#endif
	typedef volatile uint32_t __attribute__((aligned(RISCV_CACHELINE_SIZE)))
	                          LOCK[RISCV_CACHELINE_SIZE / sizeof(uint32_t)];

ロックの操作は先頭要素（`(*p_lock)[0]`）を対象とする．SILスピンロック変数
（`TOPPERS_sil_spn_var`）もLOCK型で確保し，`core_sil.h` では
`extern volatile uint32_t TOPPERS_sil_spn_var[];` と宣言する．

**型自身がサイズとアラインメントを保証する**ため，実体側でのアライン指定や，リンカスクリプト
による専用セクションへの集約は不要である（ARM依存部・ARM64依存部・HRMP3のARM依存部と同一の
記述）．`core_kernel.trb` が生成するカーネルオブジェクトのスピンロックも，この型により
自動的にラインを専有する．

なお `start_sync`（start.Sでの起動同期用）は専有させていない．起動時にのみ使用し，定常的な
競合がないためである（ARM依存部・HRMP3と同じ扱い）．

## キャッシュライン長を64とした根拠

Linuxは **RISC-Vアーキテクチャ全体で単一の64バイト**を採用しており，SoC毎には分けていない
（`arch/riscv/include/asm/cache.h`：`L1_CACHE_SHIFT 6`，`L1_CACHE_BYTES (1 << L1_CACHE_SHIFT)`．
`SMP_CACHE_BYTES` はこれと同値）．arm64も同じく6（64バイト）である．
本依存部が対象とするチップ（PolarFire SoC の U54，ESP32-P4 の HP コア）はいずれもこれに
反しないため，アーキ共通の既定値64とし，必要な場合にのみ `RISCV_CACHELINE_SIZE` を
チップ依存部で上書きできるようにしている．

参考：Linuxはロック型自体をパディングせず，`__cacheline_aligned`（`aligned(SMP_CACHE_BYTES)`
＋ `.data..cacheline_aligned` セクション）を必要な変数に選択的に付ける方式を採る．本依存部が
型による方式を採るのは，リンカスクリプトへの依存をなくし，ロックを定義するだけで専有が
保証されるようにするためである．

## 対処前に観測された状態（PolarFire SoC，4コアSMP）

対処前は，LOCK型が `typedef uint32_t LOCK;`（4バイトのスカラ）であったため，実機向けELFで
**4つのロックがすべて同一の64バイトライン（0x802e100）に同居**し，さらに頻繁に書き換えられる
無関係な変数（`syslog_count`，`sys_phase` 等）も同じラインに配置されていた．

対処後は，各ロックが `size=0x40` でそれぞれ独立したラインを専有し，他の変数との同居も
解消されることを確認している．


# タスクコンテキストの保存復帰
RISC-Vは様々な拡張が用意されており，拡張によってはタスクコンテキストとして保存・復帰するレジスタが追加される．
RISC-Vコア依存部では汎用レジスタと浮動小数点汎用レジスタに対するコードのみを記載し，他の拡張に必要となるレジスタはターゲット依存部でマクロとして記載することにする．

コンテキスト保存時の保存の順序は，次の順序とする．このような順序にしているのは，浮動小数点を含む拡張の有無によらず，汎用レジスタがスタックのトップに保存するすることで，デバッグを容易化するためである．

- タスクコンテキスト保存追加マクロによる保存
- 浮動小数点汎用レジスタの保存
- 汎用レジスタの保存

## タスクコンテキスト保存復帰追加マクロ
タスクコンテキストを保存するコードの前と，コンテキストを復帰するコードの後にそれぞれ以下のマクロを呼び出す．ターゲット依存で追加のコンテキストを保存・復帰したい場合は各マクロの内容を記述すること．これらのマクロ内ではsp以外の汎用レジスタは使用できない．spの示すスタックに保存・復帰したのち，spの値を調整すること．

- save_additional_regs_disp
	- ディスパッチ時の追加コンテキストの保存
- restore_additional_regs_disp
	- ディスパッチ時に保存した追加コンテキストの復帰
- save_additional_regs_int
	- 割込み・例外ハンドラ入口処理での追加コンテキストの保存
- restore_additional_regs_int
	- 割込み・例外ハンドラ出口処理で保存した追加コンテキストの復帰
- save_additional_regs_int_disp
	- 割込み・例外ハンドラからのディスパッチ時の追加コンテキストの保存
- restore_additional_regs_int_disp
	- 割込み・例外ハンドラからのディスパッチ時に保存した追加コンテキストの復帰


# 例外（割込みハンドラおよびCPU例外ハンドラ）の出入口処理

割込みハンドラおよびCPU例外ハンドラの入口処理は別に用意する．

ベクタテーブルのダイレクトモードと個別ベクターモードの両方に対応する．ダイレクトモードを有効とする場合は， USE_RISCV_DIRECT_TRAP マクロを定義する．

ダイレクトモードでは，t0レジスタをmscratchに一旦保存してmcauseを読み込みMSBが'0'なら例外の入口処理を呼び出す．例外の入口処理ではmscratchの値をt0に戻す．

入口処理では次の保存処理を行う．保存するレジスタは次の通りである．

- 浮動小数点数汎用レジスタ
	-  Caller save レジスタ : f0-7, f10-11,f12-17,f28-31
- 汎用レジスタ
    -  Caller save レジスタ : x1, x5-x7, x10-11, x12-17, x28-31
	-  tp(x4) : 現状使用していないがタスクのコンテキストとして保存
- リターンアドレス : mpc
- ステータスレジスタ : mstatus
	- CPUロック状態等を元に戻すために保存

汎用レジスタの保存については，RV32Eが持つレジスタを保存したのち，mpc/mstatusを保存してから，RV32Eが持たない汎用レジスタを保存する．


```
#ifdef __riscv_flen
    /* RV32Dの場合はこの時点でスタックの調整が必要?(ToDo) */
    addi sp, sp, -(TNUM_RISCV_INT_FREG * FREG_SIZE)
    sf   ft0,   0*FREG_SIZE(sp)  /* f0  */
    sf   ft1,   1*FREG_SIZE(sp)  /* f1  */
    sf   ft2,   2*FREG_SIZE(sp)  /* f2  */
    sf   ft3,   3*FREG_SIZE(sp)  /* f3  */
    sf   ft4,   4*FREG_SIZE(sp)  /* f4  */
    sf   ft5,   5*FREG_SIZE(sp)  /* f5  */
    sf   ft6,   6*FREG_SIZE(sp)  /* f6  */
    sf   ft7,   7*FREG_SIZE(sp)  /* f7  */
    sf   fa0,   8*FREG_SIZE(sp)  /* f10 */
    sf   fa1,   9*FREG_SIZE(sp)  /* f11 */
    sf   fa2,  10*FREG_SIZE(sp)  /* f12 */
    sf   fs3,  11*FREG_SIZE(sp)  /* f13 */
    sf   fa4,  12*FREG_SIZE(sp)  /* f14 */
    sf   fa5,  13*FREG_SIZE(sp)  /* f15 */
    sf   fa6,  14*FREG_SIZE(sp)  /* f16 */
    sf   fa7,  15*FREG_SIZE(sp)  /* f17 */
    sf   ft8,  16*FREG_SIZE(sp)  /* f28 */
    sf   ft9,  17*FREG_SIZE(sp)  /* f29 */
    sf   ft10, 18*FREG_SIZE(sp)  /* f30 */
    sf   ft11, 19*FREG_SIZE(sp)  /* f31 */
#endif /* __riscv_flen */
    addi sp, sp, -(TNUM_RISCV_INT_XREG * XREG_SIZE)
    sx   ra,  0*XREG_SIZE(sp)  /* x1  */
    sx   tp,  1*XREG_SIZE(sp)  /* x4  */
    sx   t0,  2*XREG_SIZE(sp)  /* x5  */
    sx   t1,  3*XREG_SIZE(sp)  /* x6  */
    sx   t2,  4*XREG_SIZE(sp)  /* x7  */
    sx   a0,  5*XREG_SIZE(sp)  /* x10 */
    sx   a1,  6*XREG_SIZE(sp)  /* x11 */
    sx   a2,  7*XREG_SIZE(sp)  /* x12 */
    sx   a3,  8*XREG_SIZE(sp)  /* x13 */
    sx   a4,  9*XREG_SIZE(sp)  /* x14 */
    sx   a5, 10*XREG_SIZE(sp)  /* x15 */
    csrr t0, mepc
    sx   t0, 11*XREG_SIZE(sp)
    csrr t0, mstatus
    sx   t0, 12*XREG_SIZE(sp)
#ifndef __riscv_32e
    sx   t3, 13*XREG_SIZE(sp)  /* x28 */
    sx   t4, 14*XREG_SIZE(sp)  /* x29 */
    sx   t5, 15*XREG_SIZE(sp)  /* x30 */
    sx   t6, 16*XREG_SIZE(sp)  /* x31 */
    sx   a6, 17*XREG_SIZE(sp)  /* x16 */
    sx   a7, 18*XREG_SIZE(sp)  /* x17 */
#endif /* !__riscv_32e */
```

## スタックポインタの調整

RISC-Vでは，外部インタフェースにおいてスタックポインタを16バイト境界（RV32Eは4バイト）にアラインさせなければならないが，あくまで外部インタフェースにおける要求事項であるため，例外発生時にそれが満たされているとは限らない．そこで，割込みハンドラおよびCPU例外ハンドラの入口で，スタックポインタが16バイト境界にアラインしていない場合には，16バイト境界にアラインするようにスタックポインタを調整する．また，出口処理でスタックポインタを元に戻せるように，調整量を保存する．具体的なコードは次の通り．

RV32Eにおいては，16バイト境界にアラインしても問題ないため共通のコードとしている．

```
	/*
     *  スタックポインタの調整
     */
    andi t0, sp, 0xf
    sub  sp, sp, t0
    addi sp, sp, -16  /* スタックポインタの調整値を保存 */
    sx   t0, 0(sp)
```

このコードで，t0には，スタックポインタが16バイト境界にアラインしている場合には0が，アラインしていない場合には4から12が入る．スタックポインタをt0の分調整して16バイト境界になるようにし，t0をスタックに保存する．

割込みハンドラおよびCPU例外ハンドラの出口では，スタックポインタの調整量をスタックから復帰し，スタックポインタを元に戻す．具体的なコードは次の通り．

```

    addi sp, sp, 16
    add  sp, sp, t0
```

```
	CPU例外が発生した状況を判断するための追加情報をスタック上から捨てる
	スクラッチレジスタをスタックから復帰する … (*p)
	CPU例外処理からのリターン
}
```

これらの処理の前に，core_exc_entry_4のラベルを置く．「CPU例外が発生した状況を判断するための追加情報をスタック上から捨てる」以外の処理は，例外からの出口で行う．

## スタックポインタが不正の場合の対策

現状対策はしていない．


# FPUのサポート

コンパイルオプションで，"F"ないし"D"サポートが指定された阿相は，RISC-V C API Specification で定義された __riscv_flen マクロが定義されている．このマクロが定義されている場合は，タスクコンテキストとして浮動小数点汎用レジスタを扱う．すなわち，常にタスク切替時に浮動小数点汎用レジスタを保存復帰する．
